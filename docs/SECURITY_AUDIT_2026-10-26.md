# Security audit and remediation — 26 October 2026

Scope: both Next.js applications, shared packages, API routes, Supabase schema/RLS/functions, cryptography and local storage, authentication callbacks, dependencies, CI, deployment configuration, and tracked source/history. This is a source-assisted engineering audit with regression testing, not independent certification or a guarantee that no vulnerabilities remain. The existing UI, palettes, fonts, and product features are preserved.

## Cleanup and performance

- Removed 18 duplicate root production dependency declarations, two duplicate app Tailwind declarations and the unused `@testing-library/jest-dom` dependency. Dependencies remain declared by the workspaces that actually use them; the lockfile removes eight resolved packages compared with the baseline audit.
- Removed the duplicated `public/icon.svg`; the existing Next.js `app/icon.svg` route remains.
- Removed 51 lines of obsolete local-vault introduction styles and 14 identical superseded CSS declarations: 73 CSS lines total.
- Removed six unused public exports, and consolidated the import endpoint's duplicate body reader into the bounded reader.
- Retained database migrations, owner/FK indexes and cryptographic costs. Low observed index use is not evidence that they are safe to delete. No password-hardening parameters were weakened to improve speed.
- No new runtime dependency or paid service was introduced. The CSS cleanup reduces unused style parsing, and byte limits bound request-buffer memory. These are targeted improvements, not a claim of measured end-user latency gains.

## Verification

Results are recorded in `TESTING.md`. Tests cover API boundaries, real PostgreSQL policies/constraints, the real SSR cookie SDK, cryptographic authentication and key handling, module CRUD, import/export, undo, search, board movement, persistence, themes, responsiveness and automated accessibility. Only fake credentials are used.

Production migrations: `20261025181734_security_session_guards` and `20261025182220_bounded_data_api_inputs`. They restrict access and add validation; they do not erase existing accounts or records. Account erasure remains an explicit user action.

## Remaining risks and limits

- CipherVault remains a development prototype for dummy credentials. This audit does not replace independent cryptographic/browser security review. An unlocked browser, malicious extension, compromised device or malicious first-party deployment can access plaintext. JavaScript memory cannot be guaranteed erased; clipboard history and old encrypted backups cannot be revoked.
- Supabase's security advisor still reports [disabled leaked-password protection](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). Enabling the provider feature depends on project settings/plan; no paid upgrade or provider Auth change was made.
- Password-reset inbox delivery/destination was not freshly retested. The user previously encountered the provider's email quota. Signup/confirmation/login/logout had been verified by the user before this audit; current callback and recovery authorization behavior is tested locally. A custom SMTP service is not configured.
- LifeHQ is not end-to-end encrypted. Its local demo stores plaintext in browser storage, and authenticated records remain accessible to authorized hosting/database operators.
- Supabase Auth rate limits and hosting protections remain the external abuse controls. There is no new distributed app-level quota, CAPTCHA, or per-user storage budget. A confirmed malicious user can still consume resources within their own authorized account. API limits do not hide or replace Supabase's public Auth/Data API.
- Direct public deployment and inbox browser checks are limited by this environment's network policy. Connector fetches can verify response content/headers, but their temporary authenticated access is not proof of anonymous deployment access. Zero npm advisories and a clean pattern-based credential scan are point-in-time findings, not complete supply-chain or secret-provenance guarantees.
